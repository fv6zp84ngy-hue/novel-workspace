# 产品需求 · 0.4.1

面向刚开始写小说的个人作者，解决正文、大纲、人物、参考文件散落，难以归类和在写作中复用的问题。

首个价值任务：输入一个想法或放入已有稿件，预览一个可编辑的写作空间；随后找到一份资料，关联章节并继续写作。保留新故事 / 已有稿件两条路径、两行八类场景和开放表达。不以真实业务增长数据为本项目效果证明。

0.3.1 将首次填写进一步降到当前动作真正需要的字段：创作方向、自由表达、作品名与资料名都可跳过；粘贴资料只要求内容，文件导入只要求文件。资料默认进入“待整理”，需要时再按人物、情节冲突、场景设定、线索时间、灵感碎片或外部参考整理。分类不决定写作顺序，也不自动改写正文。完整字段和分类理由见 [字段与分类设计](FIELD_GUIDE.md)。

## 功能层次

1. 基础写作无需模型账户：多作品、平铺大纲/章节、资料、章节任务、UTF-8 TXT/MD、规则分类、关键词查找与原文定位。
2. 保护文字：密码解锁、加密存储和备份、自动保存、版本冲突、副本、回收站、历史恢复、容量预览与人工整理。
3. 可选智能：用户自带模型账户，增量向量索引、语义查找、RAG 问答、分类建议、语义关联、草稿预览后另存。
4. 可选跨设备：用户自带 WebDAV 网盘；手动加密快照可恢复为副本，打开章节协作编辑时可数秒轮询并自动合并该章节正文。

## 交互验收

- 没有 API Key 仍能完整写作、搜索、导入、导出。
- 模型调用前说明发送范围，必须点击；分类可拒绝或撤销，草稿不覆盖原文。
- 问答展示来源标题、版本、位置与原文；过期引用或不存在的引用编号拦截。
- 网盘和模型凭据不进入 IndexedDB 或备份；跨设备不能静默覆盖远端修改。
- 保存失败保留当前编辑内容；历史清理先预览、备份与确认，再删除。

可用性目标是新手能在最短流程中拿到可编辑产物。密码保护增加一次必要设置；高级服务收在可选面板。零技术启动、零指导使用和真实作者任务完成率尚未通过真人验证。

暂不支持：亚秒级推送、在线光标、章节以外字段的自动合并、知识图谱推理、卷级目录、PDF/DOCX、文件夹监控、全站双语、密码重置。真实服务与设备发布门槛见 [验收清单](ACCEPTANCE.md)。

## 0.4.0 首次使用激活漏斗

首次使用按当前状态分为 `new_story` 与 `migrate_existing`。Treatment 的新故事路径以开放表达优先，场景模板和空白开始作为可选入口；迁移路径直接收纳粘贴或 TXT / Markdown，再引导作者搜索并打开原文或关联章节。Control 通过 `?onboarding=control` 保留 0.3.1 的入口顺序，Treatment 通过 `?onboarding=treatment` 固定新流程。除入口和路径化首次价值外，编辑器、搜索、保存和资料能力保持共用。

无模型时，本地确定性模板仍会原子创建作品、大纲、第一章、资料卡和静态任务。新故事输入保留为“创作起点”；迁移资料默认进入“待整理”。创建链路不自动把输入发送给模型，AI 仍需作者主动打开并点击发送。

首次价值口径按路径计算：新故事在可编辑产物出现后，主动成功保存一次标题/正文修改或主动添加资料；自动保存创作起点不计首次价值；已有内容路径须成功保存粘贴/导入资料，并打开搜索结果或完成章节关联。深度交互定义为同一会话完成编辑保存、资料收集、打开搜索结果、资料章节关联中的三种不同主动动作，排除系统行为、未知来源和失败操作。TTFA 与 TTFV 分别从 `onboarding_view` 计算到 `first_artifact_ready` 与 `first_value_completed`。

埋点写入独立的本地 IndexedDB，作者可从漏斗页导出匿名事件 JSON，并用 Python 标准库脚本离线汇总。事件白名单不包含正文、输入原文、作品/人物/章节名、搜索词、文件路径、模型响应或凭据。小样本只报告观察到的完成率和中位耗时，不推断统计显著性；既往业务结果不作为本原型验证结果。

版本 0.3.0 的协作目标：作者在两台设备打开同一章节并同时写作，数秒内看到合并后的文字；断网时仍可本地写，恢复网络后同步。验收须包含同一段插入/删除、中文输入法组合、断网重连、服务 412、历史恢复与真实设备实测。详见 [协作设计](LIVE_MERGE_DESIGN.md)。

0.4.1 测量修复与真实用户验收标准见 [测量口径](MEASUREMENT.md) 和 [任务手册](REAL_USER_VALIDATION.md)。真人样本为 0；不得将原型事件替代业务实验结果。
