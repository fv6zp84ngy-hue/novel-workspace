# 0.4.1 真人首次任务验证手册

状态：流程与合成素材已备好，真人完成 **0 / 至少 5 人**。自动化测试、作者本人熟悉后的演示均不能填入真人新手样本。未完成研究前只能说“建立测量与验证流程”，不能说已经验证降低 TTFV。

## 招募与分组

招募 5–8 人，覆盖两类：A 写作不足三个月、有小说想法、尚无稳定整理方式；B 有分散 TXT / Markdown 或文档素材的作者。B 的原文不必交给研究者，统一用下方合成材料。无需收集姓名、联系方式、诊断信息。不要把 ADHD 当作推断对象；可记录参与者自愿描述的操作偏好。

同一路径内人工交替分配 control / treatment，尽量平衡；每位参与者只体验一个版本，避免学习效应。链接为 `/?onboarding=control` 或 `/?onboarding=treatment`。此方案是小样本可用性观察，没有服务器随机分组，不能据此声称因果提升或显著性。

## 环境与记录

1. 获得参与者对本地行为记录、访谈记录的同意。使用一次性浏览器配置、合成素材，避免混入作者真实库。
2. 参与者自己设置测试库密码，主持人不收集密码。记录设置密码是否造成阻塞。**计量 TTFA/TTFV 从开始页出现起算，不包含密码步骤**；另外人工记录从打开网址起的全流程耗时，以免漏掉入口摩擦。
3. 给参与者编号 P01…，在研究者私有 `exports/` 保存一份记录；从 [空白记录表](validation-record-template.csv) 复制。不要把参与者记录、事件或录屏放进 Git。清空分析数据只清事件，不能清真实稿件库。
4. 一次进入开始页对应一个测量会话，刷新保持；重新进入开始页或切换版本/变体会换 ID。重复尝试分别记录，主结果只取每人第一次尝试。一个会话不等于一个真人。
5. 开始前说明可以随时停止，卡住可以直说。主持人只朗读任务目标，不演示按钮。若提供帮助，记录发生位置与提示原话，算“辅助完成”。

## 合成材料

- A 的提示：“我想写一个关于失忆侦探寻找真相的故事”。可用自己的虚构想法，不要求输入私密内容。
- B 使用四份模拟资料：[chapter1.md](../tests/fixtures/author-validation/chapter1.md)、[character.txt](../tests/fixtures/author-validation/character.txt)、[world_setting.md](../tests/fixtures/author-validation/world_setting.md)、[idea_notes.txt](../tests/fixtures/author-validation/idea_notes.txt)。先从一份开始，其余可在资料箱继续放入。
- 不测试 PDF / DOCX 转换；B 即使平时用其他文档格式，也使用同一组 TXT / Markdown 完成任务。

## 任务与观察标准

| 任务 | 给参与者的目标 | 主持人记录与事件 |
| --- | --- | --- |
| 1 开始 | A：为这个想法开始写作。B：把散落的一份内容放进工作台，之后能找到它。 | 是否理解入口；首次选路与最终选路；`route_selected`；迟疑或失败原因 |
| 2 首次价值 | A：让作品留下你想保留的一处修改。B：找到刚刚放进去的内容，或让它能在章节旁使用。 | A：产物后主动修改标题/正文并保存，或主动添加资料。B：成功导入/粘贴后搜索打开原文或关联章节；`first_value_completed`；不能只看创建完成 |
| 3 继续创作 | 接着整理并继续写这个故事，尝试添加一份资料、找回内容，让资料在章节旁可用。 | 主动编辑、收集、打开搜索结果、关联章节中的独立类型；三类才有 `deep_interaction`。不要为凑三类暗示点击 |

每个任务记录：独立完成 / 辅助完成 / 失败 / 主动退出 / 未尝试、用时、卡住位置、帮助内容和失败原因。主持人的“找回正确内容”判断与系统“打开过结果”分开记录；事件不能代替正确性观察。

任务后提问（记录回答摘要或获同意的原话，不替参与者写答案）：

- 第一次打开时，知道下一步做什么吗？
- 是否觉得需要先把资料整理好才能使用？
- 能找到刚才添加的内容吗？为什么容易或困难？
- 什么时候开始觉得这个工具有帮助？

## 结束与分析

从 [调试页](../debug/funnel.html) 导出 JSON，对照会话 ID 填记录，再放进私有 `exports/` 运行 `python3 scripts/analyze_funnel.py exports`。脚本按事件 ID 去重、只分析 0.4.1 且有开始页的完整会话；旧版和残缺/混合变体事件显示排除数。事件没有正文，但时间戳与会话行为仍应私下保管。

研究报告至少列出：实际招募/完成/退出人数、两类用户及变体分布、三个任务独立完成数/尝试人数、辅助完成数、失败原因、每条访谈证据、TTFA/TTFV（未完成者标记未完成，不能填零）、退出比例、按优先级列出的后续建议。中位时间只覆盖完成人群，必须同时展示完成率，避免幸存者偏差。

验收门槛：至少 5 位真实参与者、两类用户均覆盖、每次任务都有结果或明确缺失原因，访谈有证据。达到门槛后才更新 PROJECT.json 的 real_user_validation；研究结论与历史业务“+12%”分别报告。本手册不授权自动发消息招募或发布参与者数据。
