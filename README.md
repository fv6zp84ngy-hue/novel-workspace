# 未完待续 · Novel Workspace

**从一句想法开始，把故事、章节和资料放在一起。**

有时写作已经开始了，故事想法却留在便签，人物设定躺在另一个文档。回到正文时，还得先花力气找资料、想下一步。这个工作台把起稿、收资料和继续写放在同一个地方。

它面向刚开始写作的作者，也在朝着更适合 ADHD 写作者的方向设计：先把第一步做小；不确定的内容可以暂时收进“待整理”；标题、分类和其他整理信息都可以之后再补。你可以先留下一句话，再决定接下来写什么。

[English](README.en.md) · [使用指南](docs/USER_GUIDE.md) · [许可证：MIT](LICENSE)

## 下载后开始写

**[下载最新版完整使用包](https://github.com/fv6zp84ngy-hue/novel-workspace/releases/latest/download/novel-workspace-latest.zip)** · [版本与更新记录](https://github.com/fv6zp84ngy-hue/novel-workspace/releases)

解压后，电脑需预装 **Python 3.10+**：

- macOS：双击 **Start.command**
- Windows：双击 **Start.bat**
- Linux：运行 **sh Start.sh**

浏览器会打开本地工作台。运行不需要 Node、npm、模型账号或云端服务。第一次使用时设置资料库密码，并把密码保存在安全的地方。忘记密码无法找回。

## 从哪一步开始都可以

不必先准备完整大纲，也不必先把资料分门别类。创建新故事时，可以用自己的话写一句、选一个写作模板，或从空白作品开始。作品出现后可以直接改标题、写正文，之后再逐步添加人物、设定、情节和线索。

已经写了一些内容，也可以先粘贴一段稿件，或导入 TXT / Markdown 文件。拿不准该放哪儿时，先存进“待整理”。之后搜一句记得的原文，就能打开对应内容；需要时再把资料关联到章节。

~~~mermaid
flowchart TD
    A["打开工作台"] --> B{"现在最需要什么？"}
    B -->|"开始一个故事"| C["说一句想法、选模板，或空白开始"]
    C --> D["获得本地可编辑的作品"]
    D --> E["改标题、写正文，或加入一份资料"]
    B -->|"把已有内容放进来"| F["粘贴稿件或导入 TXT / Markdown"]
    F --> G["先放进待整理"]
    G --> H["搜索并打开原文"]
    H --> I["继续写作，或把资料关联到章节"]
    E --> J["下次回来接着写"]
    I --> J
~~~

### 内容会保存在哪里

故事和资料在当前浏览器的本地加密资料库中保存。应用默认不会把稿件上传到云端。请定期导出加密备份，并妥善保管密码；更换浏览器、设备或本地网址时，资料不会自动出现。需要在另一台设备继续写时，可以用加密备份恢复副本。

也可以自行连接模型服务或 WebDAV 网盘。每次模型调用由你主动发起，费用由你在服务商的账户承担；网盘空间也使用你自己的套餐。模型、网盘和跨设备协作的兼容性仍需结合自己的服务验证。

## 这几轮迭代做了什么

~~~mermaid
flowchart LR
    A["0.3.1<br/>把章节、资料和搜索<br/>放进本地工作台"] -->
    B["0.4.0<br/>按新故事 / 整理旧稿<br/>提供不同开始方式"] -->
    C["0.4.0<br/>不必先配置 AI<br/>即可得到可编辑作品"] -->
    D["0.4.1<br/>只把作者的主动操作<br/>算作首次价值"] -->
    E["0.4.1<br/>补充开放表达和<br/>场景入口分析"] -->
    F["接下来<br/>观察真实作者怎样完成任务<br/>目前尚未开始"]
~~~

0.4.0 的新故事入口会用本地模板建立可编辑的作品结构，并保留作者的原话；这一步没有调用模型。0.4.1 则修正了行为记录：系统自动创建内容不会被算作作者已经获得价值；作者在作品出现后主动改标题并成功保存，或添加资料，才可能完成首次价值。整理旧稿时，成功保存内容之后还需要主动找到原文或关联章节。

改完之后，合成浏览器测试可以确认：只创建作品不会触发首次价值，只改标题并成功保存会触发；自动行为也不会被计入深度交互。新故事的开放表达率只看新故事会话，场景卡片按实际可见、点击、提交和后续价值来分析。

| 变化 | 已确认的效果 |
| --- | --- |
| 首次价值口径更准确 | 自动创建不再被算作作者主动完成；标题修改并保存可以被识别 |
| 深度交互更可信 | 只累计不同类型的主动操作；失败操作和自动行为不计入 |
| 入口表现更容易分析 | 可以查看自然语言与模板的使用情况，以及场景从曝光到首次价值的过程 |
| 首次使用步骤更轻 | 无需先配置模型即可创建本地作品；资料可以先保存，稍后整理 |

项目已通过 **26 项 Node 测试、26 项 Python 测试**，Control / Treatment 浏览器流程和合成覆盖升级也已验证。GitHub 发布包只含 0.4.1 白名单文件。

**面向 ADHD 作者的真人研究尚未开展，当前完成 0 人。** 因此我们还不知道真实作者是否更容易开始、资料是否更容易找回，也没有真实 TTFV 或转化提升数据。历史业务中的“+12%”不属于这个原型的测试结果。当前可以确认的是流程和测量口径经过了合成验证。

## 更多功能

- 多个故事、章节、大纲、写作任务和资料箱
- TXT / Markdown 导入；本地分类、关键词查找和章节关联
- 本机加密保存、版本历史、冲突副本、加密备份和恢复
- 可选自带模型服务：资料分类、语义查找、带出处问答和草稿生成
- 可选 WebDAV：加密备份与单章正文协作编辑

模型与网盘服务由作者自行配置，稿件只会在主动发起相应操作时发送。详见[隐私说明](PRIVACY.md)。
